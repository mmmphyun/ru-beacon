# Ru-Beacon 마일스톤 점검 체크리스트 (INSPECTION_CHECKLIST.md)

이 문서는 하나의 마일스톤 개발(Builder 세션)이 완료된 후, **독립된 두 번째 세션(Inspector 세션)**에서 코드의 복잡도, 엣지 케이스, 사이드이펙트 및 클라우드 포트폴리오 가치를 전수 감사하기 위한 **공식 점검 기준**입니다.

Inspector 세션은 구현 코드를 작성한 세션과 분리하여 깨끗한 컨텍스트에서 실행합니다.

---

## 1. 점검 세션 실행 프로토콜

1. **Diff 추출**: 직전 개발 세션에서 생성된 커밋 범위를 확인한다 (`git diff HEAD~1..HEAD` 또는 마일스톤 브랜치 diff).
2. **`/ponytail-review` 실행**: 불필요한 복잡도와 오버엔지니어링을 1차 사냥한다.
3. **4대 관점 체크리스트 전수 평가**: 아래 4대 영역을 순차 점검하고 취약점을 도출한다.
4. **리팩터링 및 보강**: 발견된 취약점을 개선하고 `./gradlew test`를 통과시킨 후 커밋한다 (`refactor` 또는 `test`).
5. **마일스톤 최종 완료**: [MILESTONES.md](MILESTONES.md)의 점검 체크박스를 `[x]` 처리하고 푸시한다.

---

## 2. 4대 핵심 점검 체크리스트

### 영역 1: 오버엔지니어링 사냥 (`/ponytail-review`)
> 불필요한 추상화를 제거하고 가장 단순한 형태로 코드를 줄인다.

- [ ] **구현체 1개짜리 인터페이스(`yagni`)**: 인터페이스가 굳이 필요하지 않은 내부 구현 클래스에 선제적 추상화를 적용하지 않았는가?
- [ ] **단순 1:1 매퍼/DTO 중복(`shrink`)**: 내부 도메인과 계층 간 단순 복제 목적의 변환 코드가 남발되지 않았는가?
- [ ] **표준 라이브러리 재발명(`stdlib`)**: Kotlin stdlib 컬렉션 연산자나 코루틴 내장 기능으로 가능한 것을 직접 클래스로 구현하지 않았는가?
- [ ] **정적 설정 파일 남발(`delete`)**: 변경되지 않는 상수를 외부 config로 빼서 복잡도를 늘리지 않았는가?
- [ ] **스코어 측정**: `net: -<N> lines` 가능한지 평가하고 불필요한 코드 다이어트 적용.

---

### 영역 2: 엣지 케이스 및 분산 사이드이펙트 검증
> 실제 게임 서버 및 외부 네트워크 환경에서의 돌발 상황을 방어하는가?

- [ ] **네트워크 일시 단절 및 재연결**:
  - 외부 Minecraft 서버의 WSS 연결이 끊어졌을 때 지수 백오프가 정상 작동하며 메모리 누수가 없는가?
  - 재연결 시 누적된 하트비트가 한 번에 쏟아져 폭풍(Thundering herd)을 일으키지 않는가?
- [ ] **동시성 및 멱등성 (Race Condition)**:
  - 출석 버튼 광클, 동시 패킷 수신 시 `idempotency_key` 또는 DB 유니크 제약(`UQ`)에 의해 중복 실행이 원천 차단되는가?
  - 보상 예약(`RESERVED`) 상태에서 10초 타임아웃 발생 시 수량이 정상 복구(`RELEASED`)되는가?
- [ ] **스레드 안전성 (Bukkit Tick Safety)**:
  - 마인크래프트 명령어 실행 및 엔티티 조작이 비동기 스레드에서 직접 호출되지 않고 `BukkitScheduler.runTask`로 메인 틱 루프에 동기화되는가?
- [ ] **예외 전파 차단**:
  - 특정 테넌트/플러그인의 오류(역직렬화 실패, 타임아웃)가 Worker 전체 루프를 중단시키지 않고 격리되는가?

---

### 영역 3: 클라우드 엔지니어링 포트폴리오 가치 검증
> 채용 담당자 / 기술 면접관에게 강력한 클라우드 아키텍처 증거가 되는가?

- [ ] **서비스 분리 및 단방향 의존성**:
  - API, Bot, Worker 간 상호 결합(Circular dependency) 없이 Redis Streams/PubSub으로만 소통하는가?
  - `common` 모듈이 다른 하위 모듈(API/Plugin 등)을 참조하지 않는 순수 계약 모듈인가?
- [ ] **관측성(Observability) 연계**:
  - 모든 이벤트와 요청에 `correlation_id`가 누락 없이 전파되어 분산 추적이 가능한가?
  - Prometheus 메트릭 수집 지점(이벤트 처리 지연, 실패율, WSS 연결 수)이 적절히 노출되는가?
- [ ] **비용 및 리소스 통제 (FinOps)**:
  - Redis Streams에 `MAXLEN ~ 10000` 트리밍이 적용되어 OOM을 방지하는가?
  - 메모리 누수를 유발하는 정적 캐시나 무제한 컬렉션이 존재하는가?

---

### 영역 4: 실제 서비스 운영 및 데이터 분석 적합성
> 실제 운영자가 안심하고 사용할 수 있으며, 분석 가능한 데이터가 남는가?

- [ ] **감사 로그(Audit Log) 완결성**:
  - 실패 사유(`FAILURE`, `PARTIAL_FAILURE`), 실행 시각, 액터 정보가 `audit_logs` 테이블에 정확히 적재되는가?
- [ ] **개인정보 및 보안 원칙**:
  - 일반 이벤트 로그에 플레이어 IP나 디스코드 토큰 등 민감정보가 평문 출력되지 않는가?
- [ ] **장애 격리 (Graceful Degradation)**:
  - Ru-Beacon 플랫폼이 다운되어도 실제 마인크래프트 게임 서버의 일반 플레이 및 인게임 명령어가 정상 동작하는가?

- [ ] `./gradlew test` 100% 통과 확인
