# Ru-Beacon 운영 런북

## 1. 목적

공개 베타 운영자가 Ru-Beacon을 설치·설정·배포·관찰하고 장애에 대응하기 위한 절차를 정의한다.

## 2. 운영 단위

```text
Ru-Beacon Service
└── Tenant/Workspace
    ├── Discord Community
    └── Minecraft Network
        ├── Proxy Instance
        └── Backend Instances
```

Tenant 간 데이터·이벤트·토큰·권한은 분리한다.

## 3. 초기 설치

### 3.1 로컬·통합 환경

Docker Compose로 다음을 기동한다.

- PostgreSQL
- Redis
- API Service
- Bot Service
- Workflow Worker

Minecraft Plugin과 Proxy Adapter는 별도 Minecraft 환경에 설치한다.

### 3.2 Discord 온보딩

1. Discord 애플리케이션과 Bot을 준비한다.
2. Bot을 커뮤니티에 초대한다.
3. 대시보드에서 접근 가능한 Guild를 선택한다.
4. Bot 권한 검사를 실행한다.
5. 관리자 역할을 드롭다운에서 선택한다.
6. 사용자별 allow/deny 예외를 설정한다.
7. 인증 채널을 선택하거나 자동 생성한다.
8. Discord→Minecraft 허용 채널을 선택한다.
9. 시간대와 계정 연결 제한을 설정한다.
10. 2FA 정책을 `Monitor` 또는 `Enforce`로 선택한다.
11. 테스트 이벤트를 실행한다.

권한이 부족하면 설정 저장을 허용하지 않고 필요한 권한과 해결 방법을 표시한다.

### 3.3 Minecraft 온보딩

1. Proxy Adapter 또는 Backend Plugin을 설치한다.
2. 인스턴스별 인증 토큰을 발급한다.
3. 모듈 설정에 Tenant ID·Network ID·Instance ID를 등록한다.
4. TLS 연결을 확인한다.
5. 모듈 버전과 권한을 검사한다.
6. heartbeat와 테스트 이벤트를 확인한다.

Proxy 네트워크에서는 Proxy Adapter와 각 Backend Plugin을 설치한다. 단일 서버는 Backend Plugin만 사용할 수 있다.

## 4. 인스턴스 토큰

- 인스턴스별로 별도 토큰을 발급한다.
- 토큰 원문은 발급 시 한 번만 표시한다.
- 저장 시 평문 대신 안전한 방식으로 보호한다.
- 유출이 의심되면 해당 인스턴스 토큰만 폐기한다.
- 폐기 후 재발급하고 이전 토큰은 즉시 거부한다.
- 토큰 발급·폐기·재발급은 감사 로그에 남긴다.

## 5. 배포 절차

### 5.1 기본 흐름

```text
변경 작성
→ 단위 테스트
→ 통합 테스트
→ 이미지 빌드
→ 이미지 검사
→ Staging 배포
→ 기능·SLO 확인
→ 공개 베타 배포
```

### 5.2 롤백

1. 배포 버전과 변경 커밋을 확인한다.
2. 오류가 발생한 서비스만 우선 롤백한다.
3. 이벤트 계약 호환 여부를 확인한다.
4. Worker와 Bot의 중복 실행 상태를 확인한다.
5. SLO와 오류율이 회복됐는지 확인한다.
6. 원인과 롤백 결과를 기록한다.

## 6. 기능별 장애 동작

| 장애 | 기본 동작 |
|---|---|
| Ru-Beacon 전체 장애 | 일반 Minecraft 플레이 계속 |
| Minecraft 자체 명령 | 계속 사용 가능 |
| Discord 연동 명령 | 실패 응답 |
| Sandbox 이벤트 | 유실, 복구 후 자동 재실행 안 함 |
| 2FA Monitor | 관리자 접속 허용, 장애 기록 |
| 2FA Enforce | 설정된 정책에 따라 차단 |
| 출석 보상 | 연결 복구 전 지급 거부 |
| Redis heartbeat 중단 | 인스턴스 stale 판정 |
| Backend 연결 중단 | 해당 Backend 대상 명령 실패 |

Ru-Beacon 장애가 Minecraft 일반 이용을 멈추게 해서는 안 된다.

## 7. 장애 심각도

### SEV1 Critical

즉시 복구가 필요한 장애.

- 전체 서비스 장애
- 보안 사고 또는 토큰 유출
- 관리자 명령 통제 불능
- 데이터 무결성 문제
- 대규모 출석·보상 오지급

기본 동작:

- Discord 관리자 채널 즉시 알림
- 온콜 또는 운영자 확인
- 대응 시작·진행·복구 시각 기록

### SEV2 Major

- 일부 서비스 장애
- 반복되는 Workflow 부분 실패
- Discord API 429 증가
- 특정 Backend 연결 장애
- SLO 지속 초과

기본 동작:

- 대시보드 표시
- 동일 원인별 집계
- 설정에 따라 Discord digest 알림

### SEV3 Minor

- 단일 실행 실패
- 경미한 지연
- 비긴급 설정 오류
- 참고용 경고

기본 동작:

- 대시보드 표시
- 운영 로그 저장
- digest 설정 시 묶어서 알림

운영자는 `SEV1만`, `SEV1+SEV2`, `전체` 알림 모드를 선택할 수 있다.

## 8. 장애별 대응

### Redis 장애

1. Redis 연결 상태와 backlog를 확인한다.
2. 일반 Minecraft 플레이 영향이 없는지 확인한다.
3. Sandbox 이벤트를 재실행하지 않는다.
4. 인증·보상·관리 명령은 실패 처리한다.
5. 연결 복구 후 heartbeat와 모듈 연결을 확인한다.
6. 데이터 손실 범위와 영향 이벤트를 기록한다.

### PostgreSQL 장애

1. 연결 풀과 오류율을 확인한다.
2. 계정 변경·워크플로우 변경·보상 확정을 중지한다.
3. Minecraft 일반 플레이는 유지한다.
4. 복구 후 트랜잭션 실패와 미확정 보상을 조사한다.
5. 자동 재시도하지 않고 안전한 수동 복구 절차를 따른다.

### Discord API 장애·429

1. 응답 코드와 Retry-After를 기록한다.
2. 메시지·역할·채널 액션을 실패 또는 유실 처리한다.
3. Sandbox 이벤트를 과거 시점에 자동 재실행하지 않는다.
4. 관리자에게 설정된 심각도로 집계 알림을 보낸다.
5. Discord 정상화 후 연결·권한을 확인한다.

### Minecraft 모듈 장애

1. 인스턴스 heartbeat와 마지막 수신 시각을 확인한다.
2. 해당 Backend만 stale로 표시한다.
3. 플레이어 명령은 실패 처리한다.
4. 네트워크 공지는 정상 인스턴스에만 실행할지 정책을 확인한다.
5. 모듈 버전·토큰·TLS를 점검한다.

## 9. 2FA와 비상 복구

2FA 차단 기본값은 OFF다. `Monitor`에서는 접속을 허용하고, `Enforce`에서만 승인 실패·타임아웃을 차단한다.

Enforce 활성화 전 다음 내용을 운영자에게 고지한다.

> Discord 또는 Ru-Beacon 장애 시 지정 관리자도 Minecraft에 접속하지 못할 수 있습니다. 비상 복구는 서버 호스트 또는 로컬 Minecraft 콘솔에서 수행해야 합니다.

Break-glass 복구는 다음 조건을 따른다.

- 서버 호스트 또는 로컬 콘솔에서만 실행
- 영구 우회 권한 금지
- 일회성 코드·짧은 만료
- 실행자·시각·사유 감사 기록
- 최소 시간 동안만 임시 허용

## 10. 백업·복구

- 백업 보존 기간: 7일
- 초기 RPO: 24시간 이내
- 초기 RTO: 15분 이내
- 자동 전환 체계 이후 도전 목표: 3분

백업 대상:

- 계정 연결
- Tenant 설정
- Workflow 정의·버전
- 관리자 권한
- 감사 로그
- 출석 보상 설정

Redis presence와 heartbeat는 일시 상태이므로 백업 대상이 아니며 모듈 재연결로 복구한다.

복구 후에는 반드시 다음을 확인한다.

- DB schema version
- 이벤트 계약 버전
- 활성 Workflow version
- 모듈 토큰 상태
- Redis 연결
- 감사 로그 기록
- 출석 보상 중복·미확정 상태

## 11. SLO와 관측성

초기 목표:

- 인스턴스 상태 반영: 90초 이내
- 일반 이벤트 전달: p95 5초 이내
- 버튼·모달 응답: p95 3초 이내
- 보상 지급: p95 10초 이내
- 대시보드 API: p95 1초 이내

수집 지표:

- 서비스·모듈 연결 상태
- 이벤트 수신·처리량
- 처리 지연
- Redis backlog
- Workflow 실패·부분 실패
- Minecraft 명령 성공·실패
- Discord 오류·429
- DB 연결 풀
- heartbeat stale
- 출석 보상 성공·실패·소진

## 12. 개인정보·로그

- 일반 실행 로그: IP 미수집
- 관리자 로그인·원격 콘솔·권한 변경·비상 복구: 보안 목적의 IP 수집 가능
- 수집 목적·항목·보존 기간·접근 권한을 고지
- 보안 감사 로그는 지정 권한만 조회
- 감사 로그 기본 보존 180일
- 일반 실행 로그 기본 보존 30일
- 보존 기간이 끝나면 자동 파기
- 공개 베타·포트폴리오에는 익명화·집계된 값만 사용
